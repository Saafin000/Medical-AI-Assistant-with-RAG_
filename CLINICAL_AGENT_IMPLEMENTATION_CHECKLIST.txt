New Agent Name: Clinical Pre-Consultation Agent

Purpose:
  - Collect patient information before doctor visit
  - Generate adaptive follow-up questions
  - Detect emergency red flags
  - Generate structured report for doctor review

How It Fits: Extends existing multi-agent system WITHOUT modifying any 
            existing agents (RAG, Web Search, Conversation, Vision)

Technology Stack:
  - LangGraph (state machine routing - existing)
  - Groq API (LLM - existing)
  - SQLite (new patient database)
  - HuggingFace Embeddings (existing)

Integration Points:
  1. Agent Decision System (route user queries to clinical agent)
  2. RAG Agent (request medical context on symptoms)
  3. Web Search Agent (request recent treatment info)
  4. Patient Database (store collected information)

No Breaking Changes: ✓ Existing agents remain unchanged
                     ✓ Existing endpoints remain functional
                     ✓ Existing database unmodified
                     ✓ Fully additive integration

[EXECUTION FLOW - HIGH LEVEL]
================================================================================

1. User Input
   ├─ Text: "I'd like to prepare for my doctor's appointment"
   └─ Optional: Previous conversation context

2. Agent Decision System
   ├─ Analyze input
   ├─ Detect: Intent = "clinical_intake"
   └─ Route: CLINICAL_PRE_CONSULTATION_AGENT

3. Clinical Agent Execution
   ├─ Phase 1: Collect Patient Info
   │  ├─ Demographics
   │  ├─ Chief complaint
   │  ├─ Symptoms (with adaptive follow-ups)
   │  ├─ Medical history
   │  ├─ Medications & allergies
   │  ├─ Lifestyle factors
   │  └─ Vital signs (if available)
   │
   ├─ Phase 2: Query External Agents
   │  ├─ Call RAG Agent for medical context
   │  └─ Call Web Search Agent for recent info
   │
   ├─ Phase 3: Detect Red Flags
   │  ├─ Analyze symptoms
   │  ├─ Assess emergency risk
   │  └─ Generate guidance if needed
   │
   └─ Phase 4: Generate Report
      ├─ Compile all data
      ├─ Save to database
      └─ Return formatted report to user

4. Output to User
   └─ Pre-consultation report (formatted for doctor review)

[KEY DESIGN DECISIONS]
================================================================================

Decision 1: Separate Database for Patient Data
  ✓ Rationale: Isolate patient data, don't modify existing RAG/doc databases
  ✓ Implementation: SQLite in ./data/clinical_consultation_db/
  
Decision 2: Independent Agent in LangGraph
  ✓ Rationale: Minimal change to existing routing logic
  ✓ Implementation: New node in graph, selected by decision system
  
Decision 3: Read-Only Agent Integration
  ✓ Rationale: Preserve existing agent functionality and quality
  ✓ Implementation: Call process_query() / search(), never modify state
  
Decision 4: Groq API for Clinical Agent (consistent with existing)
  ✓ Rationale: Unified LLM provider, simpler ops, cost efficiency
  ✓ Implementation: ChatGroq with temperature=0.5
  
Decision 5: Adaptive Questioning with LLM
  ✓ Rationale: More natural, contextual follow-ups vs. rigid forms
  ✓ Implementation: FollowupQuestionGenerator with LLM reasoning
  
Decision 6: Multi-Layer Red Flag Detection
  ✓ Rationale: Reduce hallucination risk for safety-critical decisions
  ✓ Implementation: Keyword-based + LLM-based detection
  
Decision 7: Optional Specialized UI
  ✓ Rationale: Reuse generic /chat endpoint for MVP
  ✓ Implementation: Defer UI to Phase 5 (optional)
